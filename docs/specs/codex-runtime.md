# Codex runtime

`@stave/agent-runtime` runs one local workspace task through the installed `codex app-server` process over newline-delimited JSON. It uses the existing CLI sign-in and configured model. Stave does not read authentication files, select a model, or manage login.

## API

`runCodex({ cwd, prompt, signal?, onEvent?, executable?, timeouts? })` starts a fresh thread and one turn. `cwd` is the workspace to modify. The optional abort signal cancels the run. `executable` supports a specific Codex installation and protocol fixtures; production callers use `codex` from their executable search path.

Events report the thread identifier, text output, and item status. Results contain `kind`, `summary`, accumulated `output`, and a thread identifier when one was created.

| Result | Meaning |
| --- | --- |
| `succeeded` | The matching turn completed. |
| `failed` | Startup, protocol, timeout, or turn execution failed. |
| `canceled` | The caller aborted or Codex interrupted the turn. |
| `waiting_capacity` | Codex reported a usage limit, exhausted session budget, overload, or HTTP 429/503. |
| `waiting_user` | Sign-in failed or the run requested approval, user input, or an unsupported interactive operation. |

Only events for the created thread and turn affect the result. Events that arrive before the turn-start response are buffered within fixed limits. Completed agent messages supplement streamed text without duplicating their prefix.

## Local execution policy

Stave requests workspace-write permissions, disables command network access, excludes temporary directories from writable roots, and turns off web search. It verifies the thread's reported working directory, approval policy, approval reviewer, writable roots, and sandbox restrictions before starting a turn.

Connected tools do not share the command sandbox's network restrictions. Stave therefore disables apps, plugins, remote plugin discovery, browser use, computer use, hooks, image generation, child agents, and automatic skill MCP installation for its child process and thread. It reads the effective configuration to discover inherited MCP server names and explicitly disables each server. Configuration values and credentials are not included in run events. Unsupported server names stop the run before thread creation.

Every approval request receives a denial. Permission requests receive no added permissions; user-input requests receive no answers. Unknown interactive requests receive a protocol error. A request for the active run ends it with `waiting_user`; this API has no approval or resume operation. The prompt also restricts work to the local workspace and excludes pushes, pull requests, merges, deployments, and messages.

Workspace-write controls writes and command networking. It does not confine all file reads to the workspace. Codex remains responsible for enforcing its sandbox and managed configuration.

## Bounds and cleanup

The default request deadline is 15 seconds and the run deadline is 15 minutes. Each shutdown stage allows one second. Callers can override these limits with positive integer millisecond values.

Protocol lines are limited to 1 MiB and accumulated output to 2 MiB. Before the turn response, at most 256 events totaling 1 MiB are retained. The stderr tail is limited to 4,096 characters and is included only when the server exits unexpectedly.

Cancellation and other incomplete outcomes send `turn/interrupt` when the turn identifier is known. The runtime closes stdin, then escalates to termination and forced termination if needed. On POSIX systems the process runs in its own group; cleanup also kills descendants that outlive the app-server. Windows cleanup terminates the direct child process and does not provide equivalent descendant-group cleanup.

## Compatibility and verification

The consumed fields and approval responses were checked against JSON schemas generated by Codex CLI 0.147.0. Parsers accept additional fields and ignore unrelated notifications. Required malformed fields fail the run instead of reporting success. Other CLI versions have not been verified.

Automated subprocess tests cover streamed output, event correlation, early events, retry notifications, usage and authentication errors, approvals, inherited integration restrictions, effective sandbox checks, malformed and excessive output, deadlines, cancellation, failed startup, and descendant cleanup.

A read-only check against the installed 0.147.0 executable completed `initialize`, `account/read`, `model/list`, and `config/read`. It confirmed the existing ChatGPT account type and explicit integration-disable settings without starting a model turn. This check establishes protocol compatibility, not model entitlement or successful task execution.

Protocol reference: [Codex app-server](https://learn.chatgpt.com/docs/app-server). Configuration reference: [Codex configuration](https://learn.chatgpt.com/docs/config-file/config-reference).
